Packages y macro characters

Los packages agrupan símbolos y macro characters. Funcionan como en Common Lisp, con algunas diferencias.

Packages

Al empezar hay tres packages:

PackageContenido
almatodo lo que define ALMA, exportado
keywordlos keywords (:nombre), que se evalúan a sí mismos
alma-userel package actual al empezar; usa alma

*package* es el package actual: en él se buscan y se crean los símbolos que se leen. in-package lo cambia, y load lo restaura al terminar de cargar un archivo. 

(make-package "geo" :use "alma")
(in-package "geo")
(defun area (x) (+ x x))
(export 'area)

(in-package "alma-user")
(geo:area 3)                  ; 6

Un package creado sin :use no usa alma, así que dentro no se puede escribir defun sino alma:defun.

Diferencias con Common Lisp

  • Un package solo tiene un nombre: no hay nicknames. En su lugar, cada package puede dar un nombre local a otro.
  • Los símbolos no exportados son privados: pkg::nombre es un error al leer.
  • Los macro characters pertenecen a un package y se heredan, exportan e importan como los símbolos.
  • No hay defpackage: los packages se crean y se modifican con funciones.

Símbolos

Un símbolo es accesible en un package si está en él (es presente) o si es un símbolo exportado de un package que usa. Al leer:

SintaxisSímbolo
nombreel accesible con ese nombre en el package actual; si no hay, se crea en él
pkg:nombreel exportado de pkg; es un error si no está exportado
pkg::nombresiempre es un error
:nombreel keyword nombre
::nombreun símbolo no internado nuevo

Al escribir un símbolo se pone el prefijo necesario para volver a leerlo desde el package actual: geo:area, :k o ::x. Un símbolo no exportado de otro package se escribe pkg::nombre, aunque no se pueda leer.

Conflictos y shadowing

Dos símbolos distintos con el mismo nombre no pueden ser accesibles a la vez en un package. use-package, import y export dan un error si lo provocarían: 

(use-package "x")   ; Using x from alma-user causes a name conflict with list

shadow crea en el package un símbolo propio que tapa al heredado, y shadowing-import hace lo mismo con un símbolo que ya existe. Los símbolos que tapan a otros no provocan conflictos. 

(shadow "car")
'car                          ; ahora es alma-user::car, no alma:car

Nombres locales

Un package puede llamar a otro con un nombre propio, que solo vale cuando él es el package actual. Los nombres locales se buscan antes que los nombres globales. 

(add-package-local-name "g" "geo")
(g:area 3)                    ; 6
(package-local-names "alma-user")   ; (("g" . <package geo>))

Símbolos no internados

Un símbolo no internado no pertenece a ningún package, así que no puede chocar con ningún otro símbolo. Se escribe con :: delante y cada lectura crea un símbolo nuevo, aunque tenga el mismo nombre. Son útiles en las macros, para crear variables que no choquen con las del código que reciben.

FormaDescripción
::foolee un símbolo no internado nuevo llamado foo
(make-symbol "nombre")crea un símbolo no internado con ese nombre
(gensym [prefijo])crea un símbolo no internado con el prefijo ("G" por defecto) y un contador
(eq '::foo '::foo)            ; nil
(symbol-package '::foo)       ; nil
(make-symbol "bar")           ; ::bar
(gensym)                      ; ::G0
(gensym "X")                  ; ::X1

Funciones de packages

Un package se puede indicar con el propio package, con un string o con un símbolo, y se busca primero entre los nombres locales del package actual. Las funciones que reciben símbolos o packages aceptan también una lista de ellos. El último argumento opcional, [pkg], es el package actual por defecto.

Crear y buscar

(make-package nombre [:use packages])crea un package que usa los packages dados
(find-package nombre)el package, o nil
(delete-package pkg)borra el package; sus símbolos se quedan sin package. No se pueden borrar alma, keyword ni el actual
(rename-package pkg nombre)cambia el nombre del package
(package-name pkg)el nombre como string
(list-all-packages)todos los packages
(in-package pkg)cambia el package actual

(symbol-package símbolo)el package del símbolo, o nil

Macro characters

#c objeto llama al procedimiento asociado al carácter c en el package actual con el objeto, sin evaluarlo, y evalúa su resultado. Tras #(, #[ y #{ se leen objetos hasta la pareja ), ] o } y el procedimiento los recibe como una lista. 

(set-character-macro \! (lambda (x) (list 'quote (list x x))))
#!hola                        ; (hola hola)

(set-character-macro \[ (lambda (xs) (list 'quote (reverse xs))))
#[1 2 3]                      ; (3 2 1)

El procedimiento puede ser una función, una macro o un operador especial. El package alma exporta #( (vectores) y #{ (tablas hash).

Herencia

Un macro character se busca primero en el package actual y después entre los exportados de los packages que usa. Para que otro package lo herede hay que exportarlo, y se puede importar uno de otro package sin usarlo entero. Como con los símbolos, dos macro characters distintos para el mismo carácter no pueden ser accesibles a la vez, salvo que el package defina el suyo. 

(make-package "a" :use "alma")
(in-package "a")
(set-character-macro \[ (lambda (xs) (list 'quote (reverse xs))))
(export-character-macro \[)

(in-package "alma-user")
(use-package "a")
#[1 2 3]                      ; (3 2 1)
